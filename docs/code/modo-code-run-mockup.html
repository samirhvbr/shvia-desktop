1

Autonomia: o único controle novo

Uma pill ao lado da Aprovação, com dois valores: Um turno (o de hoje) e Até terminar. Persistida por projeto, como a Aprovação. O menu dela guarda os tetos, iterações e custo com padrão 100 e US$ 5, e o orquestrador: "Regra, sem modelo" (o padrão) ou um perfil do catálogo do gateway, no formato modelo@servidor, de preferência de outra família que o coder.

Autonomia diz se o turno continua sozinho. Aprovação diz se a ferramenta roda sozinha. São eixos diferentes e ficam em pills diferentes: uma run em Aprovação Manual continua os turnos e ainda pede cartão a cada escrita.

2

A barra da run vive entre turnos

É a barra "trabalhando" de hoje, que deixa de sumir no turn_done enquanto a run está armada. Mostra iteração e custo contra o teto, quantas vezes continuou sozinha e quantas parou em você.

Pausar segura no próximo fim de turno. Parar é o kill switch, o mesmo gesto do .loop/STOP. Os dois existem desde a primeira versão.

3

Cada continuação é uma linha visível

Quando o orquestrador decide seguir, a timeline ganha uma linha na família das ferramentas: o veredito do classificador, quem decidiu (regra, o perfil do modelo ou você), o mecanismo usado e o texto que foi injetado. Nunca fica escondido.

É o que torna a run auditável depois: quem voltar sabe onde o agente pediu confirmação e o que respondeu por você.

4

O portão humano é um cartão

A run para quando o classificador diz ASK ou quando a próxima ação é irreversível. O cartão diz por quê, em sinais, não em adjetivos: pergunta direta, migration destrutiva, política vigente.

Você responde no composer de sempre. O aviso chega na bandeja do sistema pelo canal de notificação que o Modo Code já tem.

5

O resumo é coletado, não narrado

Arquivos vêm dos diffs que passaram pelos cartões, comandos vêm com o exit code real, tokens vêm do evento usage. O agente não escreve o resumo; ele sai do que a tela já registrou.

É a tela de "voltei duas horas depois", e o mesmo desenho do checkpoint do workspace.

6

A run aparece no painel do projeto

Um fato a mais na aba Geral, na cor do estado, e a lista de decisões abaixo dele. Trocar de aba não perde a run de vista.

O Histórico passa a agrupar por run, com os mesmos totais que o resumo mostra.

Como a continuação acontece, por motor

MotorMecanismoCusto de um "continue"
Claude Codehook Stop dentro do turno: o modelo tenta parar, o classificador diz DOC, o hook devolve o motivo e o turno segue com o contexto intactoquase zero; sem turno novo
SHVIA (anna)entre turnos: no turn_done, a página classifica a última resposta e empurra "continue" na fila que já existeum turno inteiro
Codexentre turnos, igual ao anna; o codex app-server não tem superfície de hookum turno inteiro

A linha de continuação (3) nomeia o mecanismo em cada caso. A tela é a mesma nos três motores; muda só a palavra. Quem decide é o mesmo nos três: a regra, ou o perfil de orquestrador escolhido no gateway, sempre pela página, nunca pelo runner.

O que não muda

  • Cartões de aprovação continuam mandando nas ferramentas. A run nunca aprova um diff ou um comando; só decide se o turno seguinte começa.
  • Aprovação Manual / Edit / Auto e Confiar seguem valendo por cima da run.
  • Fila do composer: mensagem sua durante a run entra na fila e sai no próximo fim de turno, como hoje.
  • Abas do painel, chip de projeto, seletor de motor: mesmos lugares, mesmos nomes.
  • Fechar o desktop encerra a run. Este desenho é o do trabalho que você acompanha; o que sobrevive à máquina fechada é missão no workspace, e a ponte para lá é a frente B.
